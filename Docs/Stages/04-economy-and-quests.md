# 4단계 — 경제와 퀘스트

## 단계 목표

경제·퀘스트 조회, 일일 보상, 퀘스트 보상 수령을 서버 revision 및 멱등성 계약에
연결했습니다. 서버 저장소와 API 계약은 변경하지 않았습니다.

## 경제와 일일 보상

`ProgressionCommandService`는 현재 `EconomySnapshot.revision`을 일일 보상 요청에
전달합니다. 성공하면 서버 응답의 에너지, 코인, 일일 수령 여부와 새 revision을 그대로
적용합니다. 409이면 일일 보상을 재호출하지 않고 경제와 퀘스트를 다시 조회합니다.

## 퀘스트 보상과 멱등성

`QuestClaimIntent.Create`는 한 번의 사용자 보상 동작에 32자 멱등성 키를 생성합니다.
호출자는 응답을 확정할 때까지 같은 intent 인스턴스를 유지해야 합니다. 네트워크
타임아웃 뒤 새 키를 만들지 않고 같은 키로 재시도하면 서버가 중복 보상을 차단합니다.

요청에는 마지막 서버의 quest/economy revision을 함께 전달합니다. 성공 응답의
`replayed`를 별도 결과로 보존하고 서버가 반환한 퀘스트와 경제 스냅샷만 적용합니다.
409에서는 보상 요청을 자동 반복하지 않습니다.

## 서버 권위 규칙

클라이언트는 에너지 회복량, 일일 보상 코인, 퀘스트 진행도나 보상 코인을 자체 계산해
확정하지 않습니다. 표시 상태와 revision은 항상 서버 응답에서만 갱신합니다.

- PlayMode 8개 통과, 실패 0개, 건너뜀 0개
