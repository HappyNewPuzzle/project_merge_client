# 5단계 — 소셜과 게임 UI/UX

## 단계 목표

친구 코드·목록·친구 추가·에너지 선물 명령을 연결하고, 서버 보드·경제·퀘스트·소셜
상태를 표시하는 UI Toolkit 화면 기반을 구현했습니다. 서버 API는 변경하지 않았습니다.

## 소셜 흐름

`SocialCommandService`는 친구 코드를 공백 제거와 대문자 정규화 후 서버에 전달합니다.
친구 추가 성공 후 소셜 상태를 다시 조회해 서버 친구 목록을 적용합니다. 에너지 선물의
`recipientEconomy`는 친구의 상태이므로 내 경제 상태에 절대로 적용하지 않습니다.
서버의 `alreadyFriends`와 `replayed`는 정상적인 멱등 결과로 구분합니다.

## 화면 구조

`GameHud.uxml`과 `GameHud.uss`는 보드, 경제, 퀘스트, 친구 코드와 주요 명령 입력을
정의합니다. `GameHudPresenter`는 고정된 서버 슬롯을 버튼으로 만들고 다음 사용자 의도를
콜백으로 전달합니다.

- 빈 슬롯 선택: 아이템 생성 요청
- 아이템 슬롯 두 개 선택: 머지 요청
- 일일 보상 및 퀘스트 보상
- 친구 코드 입력 및 친구 추가

Presenter는 값을 계산하지 않고 `GameUiModel`만 렌더링합니다. 실제 명령 결과가 오기 전
아이템, 에너지, 코인 또는 revision을 낙관적으로 확정하지 않습니다.

## 오류 UX

UI 상태는 Bootstrap 진행, 준비, 네트워크 불가, 재인증 필요, 계정 정지, 충돌 후
재동기화, 일반 오류를 구분합니다. 문의에는 token 대신 서버 trace ID만 표시할 수
있습니다. 계정 정지 내부 사유는 서버 계약과 동일하게 사용자에게 노출하지 않습니다.
