# 26단계 — 드래그 앤 드롭 머지 조작

## 플레이 방법

Unity Editor에서 `Assets/MergeGame/Scenes/MainGame.unity`를 열고 Play를 누릅니다. 빈 슬롯을 짧게
누르면 Mock 서버에 아이템 생성을 요청합니다. 생성된 아이템을 같은 체인·같은 레벨 아이템
위로 드래그해 놓으면 머지 요청을 전송합니다. 마우스와 모바일 터치는 UI Toolkit Pointer
이벤트의 같은 흐름을 사용합니다.

## 입력과 피드백

8px 이상 움직이면 드래그가 시작되고 원본은 반투명해지며 아이템 유령이 포인터를 따라갑니다.
서버 스냅샷 기준으로 머지 가능한 대상만 녹색으로 강조합니다. 빈 칸, 다른 체인, 다른 레벨,
자기 자신 또는 보드 밖에 놓으면 요청하지 않고 즉시 원상 복구합니다. 최대 레벨 아이템도
대상으로 표시하지 않습니다.

## 서버 권위와 동시 입력

드롭은 `MergeRequested(source, target)` 의도만 전달합니다. 실제 레벨, 보드 위치와 revision은
Mock 또는 실제 서버 성공 응답 후 기존 `BoardCommandService`가 상태에 적용합니다. 요청 동안
전체 HUD를 비활성화해 중복 드롭을 막고 409에서는 최신 보드를 다시 받아 렌더링합니다.

## 테스트

EditMode 테스트는 동일 체인·레벨·서로 다른 슬롯만 허용하고 잘못된 레벨과 체인을 거부하는지
검증합니다. 기존 오프라인 PlayMode 흐름은 생성 두 번과 실제 머지 후 서버 응답 상태를
계속 검증합니다.

## 반응형 화면

Panel 기준 해상도를 모바일 세로형 720×1280으로 맞추고 너비·높이를 같은 비율로 반영합니다.
보드는 화면 폭의 4열 비율로 배치하고 작은 화면에서는 전체 HUD를 세로 스크롤할 수 있습니다.
Safe Area의 실제 화면 픽셀은 panel 단위로 변환하므로 Game View 배율이나 고해상도 노치에서
여백이 과도하게 적용되지 않습니다. 데스크톱과 Android 기본 창도 720×1280으로 통일했습니다.

최종 검증은 보안 스캔과 Unity 컴파일 성공, EditMode 20개 통과, PlayMode 14개 통과 및 실제
서버 통합 테스트 1개 조건부 건너뜀입니다. UXML·USS 임포트 오류도 발견되지 않았습니다.
